# Visual Language Module

Visual Language defines **meaning**, not layout. Presentation decides when and
how the visual semantics are rendered.

## Visual Upgrade v1

The module uses a four-part model:

- **WHAT** — a semantic glyph identifies the object or domain.
- **TEXT** — explicit text carries the exact human meaning.
- **STATE** — explicit state text, optionally reinforced by a sparse state lamp.
- **STRUCTURE** — Presentation owns relation, hierarchy, spacing and geography.

A semantic glyph never changes because READY, FAILED, VERIFIED or another state
changes. State remains separate.

## Construction proxy

`APERTURE_CORE` is the current strong construction direction. Its prototypes
encode a core, controlled shell, deliberate aperture and characteristic
asymmetry. Unicode geometry is a prototype/fallback representation only; it is
not the final Cerebro brand mark.

The proxy exists so Cerebro can develop a recognizable visual DNA before the
final custom glyph family is designed. Permanent semantic roles remain few.

## State color semantics

Color is sparse instrumentation, never decoration and never the sole carrier of
meaning:

- GREEN — verified / operational / ready / success
- RED — failed / blocked / critical
- AMBER — unresolved / attention / not verified
- BLUE — active / executing / current
- NEUTRAL — informational / N/A / dormant

Text remains explicit and authoritative.

## Ownership boundary

Visual Language owns semantic meaning. Presentation owns placement, fixed
columns, leader formatting, boundaries, state-lamp anchors and the Admin BIOS
renderer profile.
