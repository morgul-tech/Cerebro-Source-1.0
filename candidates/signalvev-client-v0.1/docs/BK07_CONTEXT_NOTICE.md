# BK07 Context notice route v1

This is the separate-process route selected for normal Signalvev use. The existing Context service owns PM receipts and X9 PostgreSQL custody. The Signalvev package imports no Context server modules and holds no OAuth token in a profile.

The PM host calls `context_notice_host.compose_pm(...)` with its already authenticated, current PM MCP call port. The programmatic host checks the reviewed local profile, binding and publisher NATS credential path before returning an inert publisher. `send_receipt(receipt_ref)` calls only `prepare_signalvev_notice_v1` with that receipt. The service deposits its derived pointer and returns an immutable current `MATERIAL_READY` record only on `DEPOSITED_READBACK`. The client checks the receipt hash, service-owned literal subject, host-pinned owner and fresh receipt coordinates before the existing `SendClient` publishes one D0 notice using its durable ledger. A failed service read or nondeposited state sends nothing.

The local runtime host separately calls `context_notice_host.compose_runtime(...)` with its scoped read-only MCP call port and independently scoped subscriber NATS configuration. The returned `ListenClient` remains inert until explicitly started. On each received D0 frame, its resolver calls only `transport_resolve_signalvev_notice_v1(event_id)`. The service derives the durable pointer hash and rereads the current PM cut; no caller hash or D0 schema extension is needed. The client checks the pointer and fresh PM cut, then returns owner resolution to the existing receiver. It never calls `consume_x9_pointer`, writes a disposition, or borrows a PM/X9 actor session. A superseded, mismatched or unreadable cut holds the frame.

The binding TOML must set `ports_factory = "signalvev_client.context_notice_host:make_ports"`; this is a route marker, not a callable factory for `PmX9HostPorts`. Calling `make_ports` directly refuses. The public CLI cannot inject the PM or local runtime authenticated MCP ports. These ports must come from an approved host connector for each role; local test callbacks are not live qualification. The runtime grant and read-only custody provider remain default OFF pending explicit provider approval. The existing BK07 profile remains disabled until that real connector, two NATS credential references, a new genuine PM receipt, and independent host readbacks are established. The historical BK07 event is never replayed.
