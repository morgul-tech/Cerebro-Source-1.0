## Ordinary read and sufficient model text

Use a supported authenticated ordinary tool for the already lawful question. Native document fields include `documentId`, `revisionId`, tabs and their structural content, paragraph/range indexes and named ranges where the selected tool exposes them. Treat revision identifiers as opaque. Optional `get_document.fields` metadata can locate the relevant current tab/selector or establish which depth is needed without returning body. Do not require metadata first on every read: if body is necessary anyway, that step can add a call. Metadata is neither semantic reading nor a fresh subject/scope access receipt, and omitted fields must not be invented.

A supported body response can be selected inside `functions.exec` before `text()` delivers necessary text to the model. Resolve the current tab, relevant depth and required full original from that successful response. This placement is after ordinary provider fetch and before selected model text; the body was already fetched and the model already woke. A smaller delivered response does not itself prove fewer backend bytes, fetches or wakes. Preserve full-original provenance and sufficient context for the actual decision; a short front is not a substitute when the question needs the original.

Bind native coordinates to the body revision on which they were resolved. If metadata described R1 but body is R2, or the tab/anchor moved, discard the old selector and resolve against current body or use fresh competent M0. Missing revision metadata means a cross-response match is unproven, not permission to apply old ranges. Google Docs UTF16 indexes are not UTF8 byte offsets: never relabel a native range as `UTF8_BYTE_RANGE` or invent its expected slice hash. An extracted-text digest is derived evidence, not automatically a provider-issued canonical content hash.

Assess what the receiver actually holds for this question. A prior delivery, matching revision/hash or remembered selector does not prove necessary original context survived compaction. When it is absent or uncertain, deliver sufficient current lawful text again. Never choose an empty “unchanged” response or an unexplained delta solely because the source is unchanged.

## Admission, denial, deadlines and pending work

Current `DENIED`, revoked access, representation mismatch or late result prevents the affected reuse/delivery. Old cached text must not overcome current denial, even with identical metadata/hash. Fresh competent M0 is an alternative only within independently valid ordinary access; it does not bypass denial for the same protected material. If access is unavailable, retain a content-free pending duty and its responsible owner rather than silently closing it. A later lawful retry is a new qualified read, never a blind retry or stale-body fallback.

Distinguish observed/prepared content, actual delivery and actual receiver consumption/use. A local serialized package or successful tool response does not by itself prove the receiver received or used it. Do not advance a delivered marker on observation alone; preserve pending obligations on refused, unknown, failed or late emission. This rule introduces no parallel schema, new cache, state store, timer or motor. Existing lawful state/result machinery may be used only within its own admitted binding.

The candidate's shared monotonic operation deadline is at most five seconds, across the operations its contract covers, with remaining time honoured at describe/open/read/confirm, fresh final description, serialization/state and actual emission. Starting a timer only after fetch does not qualify elapsed fetch time; a check before a later queue is not a demonstrated delivery lease. A late body or emission must not become payload or a delivered state. Ordinary reader success has its tool's documented timing semantics; absent evidence of the candidate's complete deadline, report that limitation rather than asserting a five-second candidate guarantee.
