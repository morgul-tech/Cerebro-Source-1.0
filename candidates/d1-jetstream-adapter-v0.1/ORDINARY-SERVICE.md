# Ordinary BK11 component integration

This is the existing d1-jetstream-adapter component. The installed entry is
`runtime_once.py --admission <root-owned role profile> --action normaldrift`.
The captured factory is `edge_factory_snapshot.open_runtime`; both normal and
family profiles pass through this entry. A family profile goes through the same
`edge_adapter`, `production_factory`, `FamilyPlanRuntime` and `ordinary_runtime`.
The profile selects an existing qualified host/role/session/assignment/source
manifest, not an individual task, message, material or prior operation.

Ordinary actor register/send/accepted-page read and return stay on the existing
Context actor tools. The EDGE role client is not an actor or issuer credential.
No privileged file, program generation, SSH session or new installation is
required per message. Supported two-family policy enums and existing fixed
transport/token security policy remain program constraints, not arbitrary input.
The normal service discovers current scoped rows through the authenticated owner
port. Its role-private cursors and fences are data; they grant no rights.

Publisher ticks use existing conditional owner claims and normal transport
publication. Receiver ticks first observe bounded current backend custody and
then pull, validate, accept/read back and ACK through actual lease guards. The
wrapper implements the runner's durable family-progress callback. Durable
backend custody and a transit ACK are not actor model use or completed work.
Expired pointers cannot be republished: only current scoped server proof of
durable backend disposition permits cursor progress past an expired owner row.

If an operation fence exists, normaldrift performs a proof-only reconciliation
tick. It performs no broker/discovery/cursor sweep. V1 fences remain readable;
new V2 fences retain the original and every intermediate interrupted attempt.
The predecessor's exact legacy `bk11attempt` reference is preserved alongside
new family `a:` references. Neither is translated, discarded or treated as
authority: the existing bounded server reference syntax and actual current
authenticated assignment-specific proof are required for each exact target.
Server proofs must match the current assignment/family/lease/operation and each
exact prior attempt. Protected server absence, if admitted by the existing
server contract, is not a client inference. Unknown proof or CLOSE keeps fences.
Only committed own CLOSE, durable role/family results and successful outer
cleanup permit the ordinary runner to remove its fences. The next normal tick
uses the same code to process pending current messages. An ambiguous ingress
hold still requires its rightful owner; it is not silently cleared.

Existing proof-only reconciliation contract: runtime `bk11_service_custody.py`
control_attempt recovery branch looks up the target in the authenticated current
assignment. It can prove protected absence or an actual reconciled duty; it
does not prove broker absence. A target with unresolved obligations remains
unreconciled. This component cannot override that result, force a lease, change
a grant, reset a budget or clear a server fence.

Task lifecycle, register/send authorization and recipient completion state stay
with their actual owners. Use the E2 accepted-material consumer helper via the
actor's ordinary qualified read callback. A scan cursor is not a completion
watermark. Empty-with-next is nonterminal; later acceptance requires a fresh scan
from the beginning with a separate stable scoped completed-work ledger. Only
actual actor work may mark completion. Existing notification expiry does not
renew or revoke independent read admission. Preserve the precise old-carrier
and read-permission-expiry errors and actual owner action.

Installation is a separate one-time qualified maintenance action: publish and
read back this Source delta and E2's compatible Context delta through A1; bind
the exact published runner/core/snapshot/profile bytes, preserve old installed
snapshot, current admissions and rollback witnesses, qualify actual serving
runtime/current rights, then use the existing protected maintenance port. Do not
reuse spent key/release operations. Admission pins and family factory pins must
agree. No old token budget, state, broker, timer, lease or task is reset merely
to install. Existing state remains at its owner. No total Human/key TTL is added.

Local qualification runs `python -I -B check_ordinary_connection.py` from the
enclosing task preparation directory. Seven cases exercise the actual ordinary
runner/factory/two-family/publisher/receiver path with explicit inert custody,
HTTP authority and in-memory transport. Disposable files are cleaned by the
fixture. This is not deployed auth, broker, PostgreSQL or recipient-use proof.
Preserve earlier valid custody/token/native/transport evidence within its scope.

Whole acceptance still requires compatible loaded installation and actual
ordinary register/send/transport/accepted discovery/FULL material use/return,
with interrupted continuation and next messages supported by the same program.
The concrete pending X9 journey and the separate W direction are not merged or
replayed. Current capacity is measured once through the existing legitimate
owner port during necessary maintenance; unchanged limits are not raised or
reset. An honest unresolved owner boundary is not a product-ready verdict.
